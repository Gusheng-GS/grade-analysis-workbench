## 三、过程中踩到并解决的四个坑

这些都是**实测发现**的，写下来避免以后重复踩：

### 坑 1：直接访问根路径会被 401 拒绝

`dsh web` 打开的不是 `http://127.0.0.1:3080/`，而是**带进程 token 的地址**：

```
dsh web: http://127.0.0.1:3080/?token=xxxxxxxx
```

浏览器用这个地址换取签名 cookie，之后才重定向到干净的根页面。

**实测**：程序直接请求根路径 → `HTTP 401`。所以"打开浏览器"这个动作**必须交给 dsh 自己做**，启动器不能代替。

### 坑 2：启动器里加了 `--no-open` 反而坏事

一开始我让启动器自己解析 URL、自己开浏览器，于是加了 `--no-open`。结果因为坑 1，拿不到 token 就打不开。

**结论：不要加 `--no-open`**，让 dsh 自己开浏览器。

### 坑 3：重定向子进程输出会让服务起不来

用 `RedirectStandardOutput/Error`（管道）时，服务启动后端口一直不监听。原因：dsh 内部还会再开子进程，管道句柄在 GUI 进程下容易出问题。

**结论：`CreateNoWindow = true` + `WindowStyle = Hidden` + 不重定向**，实测 8 秒内就绪。

### 坑 4：exe 放错目录

启动器按"自己所在目录"找 `runtime\` 和 `app\`。最初我把它编译到 `dist\` 子目录，于是它去找 `dist\runtime\node.exe`，报"缺少运行环境文件"。

**结论：exe 必须与 `runtime\`、`app\` 平级。**

### 附带坑：bat 文件的编码

`.bat` 由 `cmd.exe` 按系统 ANSI 代码页（中文 Windows = GBK/936）解析。若存成 UTF-8，中文会乱码，甚至出现**行首字符丢失**（`netstat` 变成 `tstat`）导致脚本报错。

**结论：含中文的 bat 必须用 GBK 编码 + CRLF 换行**，且不要用 `chcp 65001`。本项目用 `launcher/make_stop_bat.py` 生成以保证编码正确。

## 四、一个必须告知的版本差异

| | 版本 | 说明 |
|---|---|---|
| **成品（exe 版）里的 DSH** | `0.1.5-rc.2` | 来自本机原有的 npm 安装 |
| **已拉取的源码 `dsh-src\`** | `0.2.0-rc.2` | 官方仓库 master，**更新一个版本** |

**这意味着**：当前成品是"用现有安装包壳子"，**还没有用到新源码的任何东西**。

后续如果要在源码上开发（比如改造 WebUI 加成绩分析面板），需要先构建源码，再替换 `app\` 目录。构建命令（来自官方 `AGENTS.md`）：

```sh
pnpm install
pnpm run build        # 需要 pnpm 11.7.0、Node ^22.19 || >=24
pnpm --dir apps/desktop run package:win:x64:dir   # 若走官方 Electron 外壳
```

> 注意：官方 `apps/desktop` 是 **Electron 自绘窗口**，不是"打开浏览器"。与本轮成果的路线不同，若要采用需明确改动策略。
