# docs 里放什么

这里放**除根目录 README 之外**的文档。

## 现在有什么

| 文件 | 内容 |
|---|---|
| `开发记录.md` | 从需求到成品的完整开发过程：做过什么、推翻过什么、踩过哪些坑、为什么这么选 |
| `exe化改造记录.md` | 把 DSH 改造成"双击 exe 开浏览器"的那一段专门记录 |
| `RELEASE-NOTES-v0.1.2.md` | 当前版本的发布说明（安全更新）。发 GitHub Release 时正文整篇贴这份 |
| `RELEASE-NOTES-v0.1.1.md` | 0.1.1：自动更新功能（留档） |
| `RELEASE-NOTES-v0.1.0.md` | 0.1.0：首个公开版（留档） |
| `图片/` | README 与文档里引用的截图（见里面的 `说明.txt`，命名有约定） |

## 加新文档的约定

- 一个主题一个文件，文件名用中文说清楚是什么（比如 `脱敏方案说明.md`、`五岳导出格式.md`）。
- 新文档写完后，**回来在这个表格里加一行** —— 否则别人（包括几个月后的你）翻不到。
- 与某个版本绑定的东西（发布说明、迁移步骤）带上版本号，比如 `RELEASE-NOTES-v0.2.0.md`；
  与版本无关的长期文档不用带。
- 贴图放在 `docs/图片/` 下，引用用相对路径。

## 哪些东西不放这里

| 内容 | 该放哪 |
|---|---|
| 项目简介、安装步骤、功能截图 | 根目录 `README.md` |
| 用到的第三方代码与协议 | 根目录 `THIRD-PARTY-NOTICES.md`（打包脚本会读它的固定位置，别挪） |
| 许可证原文 | `licenses/` |
| 目录树、如何构建 | 根目录 `项目结构说明.md` |
