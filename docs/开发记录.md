## 一、项目是什么

给高中**班主任**用的成绩分析工具。老师把五岳阅卷系统导出的成绩文件夹导入进去，
程序在本地解析出分数、名次、每题得分率，再借助 AI 生成：

- **分析台**：全班概况、各科均分、最该讲的题、每个学生的历次表现与趋势图
- **方案台**：每个学生的补弱清单 + 两周训练安排，可导出 Word / PDF 打印发下去

**交付形态**：一个双击就能跑的文件夹（`启动.bat` → 浏览器打开 WebUI），
老师电脑上不需要装 Node、不需要开发工具。

**底层**：把 DeepSeek Harness（DSH，MIT 协议）当作运行外壳，把工作台界面以 iframe
注入它的 WebUI；右下角圆按钮可以在"成绩工作台"和"原生 DSH 界面"之间切换。

## 五、关键设计决策（为什么这么做）

| 决策 | 原因 |
|---|---|
| 界面用**单文件自包含 HTML**，不搞前端工程 | 老师机器上只有 node.exe，没有构建工具链；单文件最容易注入、最容易更新 |
| 界面由**生成器**产出，不手改产物 | 产物 5500 行、含内联解析器；手改必然和源码分叉 |
| 五岳解析**移植成 JS**，而不是让老师跑 Python | 老师电脑不会有 Python；浏览器里 SheetJS + 纯 JS 能做到零依赖导入 |
| 保留 Python 参考实现并做**逐字段比对** | 移植最大的风险是"数字悄悄算错"，用旧实现当标准答案才敢换 |
| 折线图**自己用内联 SVG 画** | 离线可用、不背第三方库的协议与体积、只需要折线和悬停 |
| 考试按 **examId 隔离存储**，`DATA` 只指向"主考试" | 数据隔离与界面改动解耦：既有代码继续读 `DATA`，不用全量重写 |
| 脱敏做成"**出去换代号、回来换真名**" | 只脱敏不还原的话，AI 写出来的方案正文里全是"学生07"，打印给学生就废了 |
| 更新用**覆盖文件**而不是移动目录 | 实测 `Directory.Move` 在本机被拒（IOException 访问被拒绝），逐文件覆盖可行且风险小 |
| 不重定向启动器的子进程输出 | 实测重定向 stdout/stderr 会导致服务起不来 |
| 交付版内置**空白数据**，老师自己导入 | 不带任何学生信息交付；数据归属老师本人 |
| 端口固定不自动选 | 端口决定 localStorage 的来源，换端口等于成绩/密钥全部重来 |

## 六、踩过的坑（按类别，都经实测）

### 6.1 Windows / 进程 / 端口
| 现象 | 原因 | 解决 |
|---|---|---|
| 双击 .html 打不开 | 本机 .html 文件关联指向已被移除的 IE | 预览脚本用 Edge/Chrome 完整路径打开 |
| `taskkill /F /PID` 返回"拒绝访问" | 本机权限模型 | 改用 PowerShell `Stop-Process -Force`；停止脚本里加兜底 |
| 用 `start "" exe` 起服务，关脚本后服务也没了 | 子进程随控制台退出 | 改成 `start "标题" cmd /k …` |
| 代理/端口类工具看不到进程命令行 | `Get-CimInstance`、`wmic` 在本机不可用 | 改用启动器自己写日志来定位 |
| 判断"服务好没好" | 端口被占 ≠ 服务就绪 | 启动.bat 主动轮询端口，通了才开浏览器 |

### 6.2 编码 / 批处理
| 现象 | 原因 | 解决 |
|---|---|---|
| bat 里中文乱码 | cmd 按 ANSI 代码页解析 bat | bat 必须 GBK + CRLF |
| GBK bat 在 UTF-8 控制台下也乱码 | 控制台代码页是 65001 | bat 开头加 `chcp 936 >nul` |
| 说明书在记事本里乱码 | 无 BOM 的 UTF-8 | 统一写 UTF-8 **带 BOM** + CRLF |

### 6.3 DSH / 注入 / 更新
| 现象 | 原因 | 解决 |
|---|---|---|
| 更新提示成功但界面还是旧的 | 集成那步把 `update\_workbench.html`（旧）复制回前端，覆盖掉刚装的新页面 | 安装时先把包里的页面同步回 `update\`，再集成 |
| "只改界面"的小包被判"格式不对" | `FindAppDir` 只认 `dsh\lib\bin.js` | 放宽判据：也认 `dsh-web-frontend\dist` |
| 换了新包浏览器还是旧界面 | iframe 的 `?v=<时间戳>` 没变，吃了缓存 | 重新注入 index.html 刷新时间戳 |
| 工作台不显示 | 排除顺序：端口、注入、`_workbench.html` 是否被部署 | 分别验证 |
| 早期"导入成绩"是空壳 | 代码里只统计了文件行数发给 AI，从未解析分数 | 移植真解析（阶段 7） |

### 6.4 前端 / 数据
| 现象 | 原因 | 解决 |
|---|---|---|
| `XLSX.read(ArrayBuffer)` 解析成乱码、行数都不对 | SheetJS 的类型判断认不出 `ArrayBuffer` | 先转 `Uint8Array` 再传 |
| 得分率并列的题顺序错乱 | JS 对象把"数字型键"（如 `"14"`）排到最前，与 Python dict 插入序不同 | 另存 `itemOrder` 数组，按行序遍历 |
| 均分偶尔差 0.1 | Python `round()` 是银行家舍入 | 用 `pyRound1`/`pyNumStr` 复刻 |
| 学生分差/趋势显示不对 | 学生可能某次未参加 | 数据点置 `null`，折线**断开**、表格标"未参加" |
| 数据清了就找不回 | 全部数据只在浏览器 localStorage | 加"导出备份 / 从备份恢复" |

### 6.5 工具链 / 我自己的失误
| 现象 | 原因 | 解决 |
|---|---|---|
| 无头 Edge 起不来（mojo: 拒绝访问） | 沙箱不允许 Chromium 建 named pipe | 浏览器行为改用 **jsdom** 测 |
| 文件被清成 0 字节 | `python -c` 里写 `open(p,'w')` —— 先截断，再因参数错误抛异常 | 改用编辑工具或写成 .py 文件 |
| 超长路径删不掉（WinError 145） | `shutil.rmtree` 不支持 `\\?\` 前缀 | 自己遍历 + 前缀逐层删 |
| 体检"通过"但漏检 | 长路径文件读失败被静默跳过 | 读不了的文件要**报失败**，不能当通过 |
| 测试互相污染 | 启动器只杀 launcher，node 子进程继续占端口 | 测试自己清理子进程；各测试用独立端口 |
| 误杀开发实例 | 进程匹配写太宽（`*DSH成绩分析工作台*` 命中了 `…-开发文件\runtime\node.exe`） | 匹配收窄到 `…\DSH成绩分析工作台\runtime\node.exe`，并加测试守住 |
| 解压丢文件 | 包内最长路径 195 字符，微信接收目录很深 | 说明书里明确"解压到桌面或 D 盘" |

## 八、交付流程

### 8.1 打包
```powershell
python data\gen_home_html.py        # 生成空白版页面（默认；--with-data 才是带真数据的版本）
python data\sync_workbench.py       # 页面 + SheetJS 同步到交付包与前端，校验 md5
python data\reintegrate.py          # 重新注入 index.html（刷新 ?v= 防缓存）
python data\preflight.py            # 交付前体检（必须通过）
python data\make_zip.py             # 完整包
python data\make_update_patch.py    # 小更新包（给已装新启动器的老师）
```

### 8.2 两种包的选择
| 老师当前状态 | 发哪个 | 为什么 |
|---|---|---|
| 手上是最早那一版（启动器等都不含修复） | **完整包** | 旧启动器会覆盖回旧页面，小包装不上界面改动 |
| 已装过"修复版启动器" | 小更新包 | 0.5 MB，手工覆盖即可 |

### 8.3 更新机制（已实测）
把 `.zip`（内含 `app/` 目录）放进 `update\` → 双击 `停止.bat` → 双击 `启动.bat`
（发现 zip 会自动转交启动器）→ 弹"更新完成" → 再启动一次生效。

### 10.8 本轮踩的坑（工具环境为主）

- 沙箱里 pwsh 与 node **都出不了网**：gnu.org 拿 403、`raw.githubusercontent.com` 解析到内网地址，
  `npm install` 因 npm 缓存目录 `EPERM` 失败。于是：许可证原文改为从随包 LibreOffice 里挖，
  测试改为 `NODE_PATH` 指向 `_devtools\node_modules` 才跑起来。
- `zipfile.extractall` 遇到 >260 字符路径直接 `FileNotFoundError` → 逐条解压并加 `\\?\` 前缀。
- `taskkill /F` 会被拒（"Access denied"）→ 一律用 `Stop-Process -Force`。
- 裸 `GET /` 抓不到页面（dsh 的首页要带进程 token）→ 验证改为查磁盘上的
  `dist\index.html` 与 `/_workbench.html`。
- 打包自检一度误报：`THIRD-PARTY-NOTICES.md` 里"改名前叫 DSH成绩分析工作台"这句被当成残留 →
  检查范围收窄到 `.bat`/`.txt`/`.html`/`.js`。
- PowerShell 里 `[System.IO.File]` 用的是进程当前目录、不是 `cd` 之后的目录 → 改文件一律传绝对路径。
- **GitHub Release 会悄悄去掉附件名里的非 ASCII 字符**：第一次上传的
  `成绩分析工作台-v0.1.0-windows-x64.zip`，在 Release 上变成了 `-v0.1.0-windows-x64.zip`
  （中文整段消失，只剩那个连字符；源码 zip 的自动命名也受同一规则限制）。
  用 Release API 的 `assets[].name` 和 `digest` 字段才看清真相——文件字节没坏（digest 与本地一致），
  坏的只是名字。修法：`make_release_zip.py` 加了 `--slug`，**zip 文件名用 ASCII、
  包内文件夹仍是中文**；README / 发布说明里都加了一句解释。
  教训：凡是"交给平台托管"的名字（附件名、tag、仓库名），先假设它只吃 ASCII。
